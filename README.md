# SnapFlow Go

Production-развёртывание и настройка GitHub Actions: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). `compose.yaml` предназначен для production; локальный стенд и тесты запускаются через `compose.test.yaml`.

Бэкенд личного хранилища изображений: регистрация/вход, пакетная загрузка, зашифрованные оригиналы и JPEG-превью, проверка владельца и удаление. Gin, PostgreSQL/GORM, RabbitMQ, локальное или S3-хранилище через общий интерфейс.

## Запуск

Нужен Docker Compose v2; Go и серверы БД на хосте не требуются. Команды из корня этой копии:

```powershell
Copy-Item .env.example .env
docker compose -f compose.test.yaml up --build -d --wait
docker compose -f compose.test.yaml --profile test run --build --rm tests
docker compose -f compose.test.yaml --profile test run --build --rm smoke
```

HTTP: порт задаётся в HTTP_PORT; в текущем .env используется http://localhost:8083/. PostgreSQL и RabbitMQ доступны только внутри Docker. Миграции выполняет migrate до server, worker и outbox. Процессы приложения работают под UID 10001 из /app. Данные БД, брокера и общий каталог изображений имеют отдельные постоянные тома. Одиночный RabbitMQ с quorum queues сохраняет сообщения, но не является отказоустойчивым кластером.

```powershell
docker compose -f compose.test.yaml logs --tail=100 server worker outbox
docker compose -f compose.test.yaml down
```

down сохраняет тома. Для изолированной установки используйте одинаковый -p NAME во всех командах и свободный HTTP_PORT. Изменение паролей в .env само по себе не меняет пользователей в уже созданных томах.

## Приём, доставка и staging

Файл читается с ограничением 10 MiB, проверяются формат и размеры. На запрос действует 128 MiB, максимум 32 файла; декодирование ограничено 40 млн пикселей и 12000 пикселями по стороне. Перед записью staging создаётся учётная строка UploadOperation. В общем хранилище private/staging лежат настоящие AES-GCM ciphertext, не публичные URL. Состояние accepted и OutboxEvent фиксируются одной транзакцией; только после неё файл попадает в успешный HTTP-ответ. Ошибка части файлов не отменяет ранее принятые файлы; возвращаются только принятые имена.

Отдельный outbox-процесс выбирает события с FOR UPDATE SKIP LOCKED. Транзакция удерживает строку до publisher confirm и проверки mandatory returns; после этого отмечает опубликованной. Несколько экземпляров безопасно разделяют работу. При аварии после публикации до отметки событие будет отправлено повторно: гарантия at-least-once. После 20 неудачных попыток событие и загрузка помечаются failed. Исходник и промежуточные файлы удаляются фоновой уборкой, квота освобождается после успешного удаления. Событие остаётся для диагностики; его ручной повтор не восстанавливает загрузку. Для новой попытки пользователь загружает файл заново.

Сообщение version=2 содержит ID задачи, request_id, тип, attempt и payload: staging_key, filename, user_id. Байтов/base64 файлов в нём нет; лимит сообщения 64 KiB. Пространство очередей snapflow.v2 отделено от прежнего формата. Миграция старых очередей не реализована; стенд этой копии не подключается к внешним данным.

Worker читает staging, обрабатывает фотографию и фиксирует метаданные вместе с состоянием complete. Получить список: GET /api/images?page=1&limit=20. Загрузка возвращает HTTP 202 и идентификаторы файлов; GET /api/uploads/{filename} возвращает processing, ready, failed, deleting или deleted. Ошибка обработки хранится не менее 30 дней и до завершения уборки. Удаление записывается в PostgreSQL и повторяется до успешного удаления оригинала, миниатюры и staging. Квота освобождается только после подтверждённого удаления.

RabbitMQ: persistent messages, durable quorum queues, manual ack после завершения, ограничение prefetch (1–32), три попытки обработки с TTL-задержкой 5 секунд и parking очередь. Повтор/parking передаётся с confirm до ack исходной доставки. Quorum dead-lettering использует at-least-once, без плагина задержек. При обрыве соединения объявление/подписка восстанавливаются с паузой; неподтверждённая доставка повторяется. Exactly-once не обещается. Повтор самого HTTP upload создаёт новую операцию; Idempotency-Key API пока нет.

## Хранилище и ключи

Compose по умолчанию STORAGE_DRIVER=local, общий том /app/data/storage и отдельный LOCAL_STORAGE_KEY. Для S3 задайте STORAGE_DRIVER=s3 и TWS_* из примера. Фабрика вне Compose по умолчанию оставляет S3. Общая оболочка выполняет AES-256-GCM, физические backend перемещают ciphertext. S3-ключи оригиналов/превью и вывод ключа SHA-256(TWS_SECRET_ACCESS_KEY) сохранены. Переключение backend не переносит данные; смена секрета не перешифровывает старые объекты. Ключ необходим для восстановления резервной копии.

S3_REQUEST_TIMEOUT_SECONDS ограничивает один HTTP-запрос к S3; по умолчанию 30 секунд, положительные значения — от 1 до 3600, ноль выбирает значение по умолчанию. SDK может выполнить несколько повторных запросов, поэтому общее время операции может быть больше. Отмена HTTP-загрузки прерывает запрос staging к S3.

Локальный каталог принадлежит приложению; операции не принимают пути вместо filename и отклоняют символические ссылки. Он не должен изменяться посторонними процессами одновременно с приложением. S3-контракт и ошибки проверяются подменой SDK с настоящим шифрованием; реальное облако не требуется и не проверялось.

## Логи и API

Логи компонентов приложения — JSON с уровнями INFO, WARNING, ERROR, FATAL. X-Request-ID проверяется, возвращается клиенту и проходит через outbox, AMQP headers/envelope, worker и повторы. SQL-текст/параметры, пароли, токены, файлы и персональные поля не выводятся; ошибки имеют безопасные error_code. Логи инфраструктуры и вывод Go test имеют собственный формат. Prometheus-метрики не реализованы; request_id не является меткой метрики.

Пользовательские запросы используют JWT после входа. Администратор управляет приглашениями и ограничениями пользователей через API.

## Проверки и дальнейшая работа

Контрактные тесты проверяют диск, шифрование и S3-адаптер; интеграционные — настоящие PostgreSQL и RabbitMQ, outbox rollback/SKIP LOCKED, дубли после неопределённого подтверждения, ограниченные ошибки, повторы и parking. Smoke проходит JPEG/PNG/GIF, включая 10 MiB, через HTTP → staging → outbox → RabbitMQ → worker → PostgreSQL и зашифрованный том; проверяет чтение, владельца и физическое удаление.

Коллекция Bruno проверена на изолированном стенде. Скрипт tools/Test-Recovery.ps1 пока относится к предыдущему контракту.

Удалены только старые сборочные server, worker и архив go1.21.5.linux-amd64.tar.gz: они были исключены из Docker-контекста, приложение собирается из исходников Go 1.23.11. Пользовательские данные и исходная папка не удалялись. План следующего небольшого этапа — docs/REFACTORING_PLAN.md. Измерений нагрузки и доказанного бизнес-эффекта здесь нет.

При первом запуске сервис migrate создаёт администратора из ADMIN_NAME, ADMIN_EMAIL и ADMIN_PASSWORD в .env. Все три значения обязательны; .env.example содержит пустые поля. Пароль сохраняется как bcrypt-хеш. Повторный запуск не меняет существующую учётную запись; совпадение email с обычным или удалённым пользователем приводит к ошибке. Изменение .env не меняет пароль существующего администратора.

Регистрация доступна по приглашению. Администратор создаёт его через POST /admin/invites, задавая access_to (UTC) и memory_limit в байтах. Приглашение действует 24 часа и используется один раз. POST /api/register принимает invite_code; POST /api/verify-email принимает email и шестизначный code из письма. Код действует 10 минут, допускается пять попыток. Повторная отправка — POST /api/resend-verification, не чаще раза в минуту.

Локально письма принимает Mailpit: http://localhost:8025. Swagger UI: http://localhost:8083/swagger/ при текущем HTTP_PORT. Для реальных писем настройте SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM и SMTP_REQUIRE_TLS=true. После срока доступа загрузки запрещены; через 15 суток фотографии удаляются, если администратор не продлил доступ. Уведомление об окончании срока повторяется до принятия почтовым сервером.

Неудачные входы ограничены пятью на IP за скользящие 10 минут через Redis; успешный вход сбрасывает счётчик. При недоступности Redis вход закрывается. Если приложение находится за прокси, укажите IP-адреса или CIDR доверенных прокси в TRUSTED_PROXIES; при пустом значении заголовки не используются для определения IP. JWT_SECRET обязателен. 

Миграции выполняются golang-migrate при старте. Первая миграция создаёт базовую схему и совместима с предыдущей схемой AutoMigrate; последующие миграции добавляют поля статуса и очередь писем. Письма подтверждения записываются в БД в зашифрованном виде и отправляются фоновым процессом; устаревшие коды не отправляются. Уведомления об истечении срока обрабатываются отдельно от физического удаления. При смене JWT_SECRET ещё не отправленные коды могут потребовать повторного запроса.
